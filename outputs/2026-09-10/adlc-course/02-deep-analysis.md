# ADLC — Глубокий анализ

**Источник:** курс Григория Добрякова «AI-Driven Development Lifecycle»  
**Дата анализа:** 2026-09-10

---

## 1. Суть курса в трёх предложениях

ADLC — это мысленный эксперимент, доведённый до систематического описания: что будет, если убрать человека из каждой фазы SDLC? Курс проходит по 14 фазам и на каждом шаге честно показывает, где замена работает, а где ломается. Финальный ответ: человека нельзя убрать из системы целиком — остаётся один принципал, который отвечает за цели, риск и рубильник.

---

## 2. Ключевые концепции

### 2.1. ADLC vs AI-assisted SDLC

| Критерий | AI-assisted SDLC | ADLC |
|----------|------------------|------|
| Роль AI | Ускоритель, помощник | Полноценная роль |
| Человек | Остаётся на месте | Уходит из фазы |
| Единица работы | Строка кода, черновик тикета | Задача → готовый PR |
| Пропускная способность | Растёт | Роль передаётся |
| Ответственность | На человеке | На принципале (ф.14) |

### 2.2. Петля ADLC (14 фаз)

```
Ideation → Discovery → Marketing → Requirements → Architecture → Formation → Planning → Implementation → Code Review → Testing → Release → Operations → Maintenance → Governance
                                                                                                                                    ↑                                                                        │
                                                                                                                                    └────────────────────────────────────────────────────────────────────────┘
```

**Ключевой момент:** фаза 13 (Maintenance) замыкает петлю обратно на фазу 1 (Ideation). Продукт инициирует собственное развитие.

### 2.3. Метрика «остаток человека»

Курс вводит необычную метрику — процент человеческого участия в каждой фазе:

| Фаза | Остаток человека |
|------|------------------|
| Ideation | 93% |
| Discovery | 86% |
| Marketing | 80% |
| Requirements | 73% |
| Architecture | 66% |
| Formation | 60% |
| Planning | 53% |
| Implementation | 46% |
| Code Review | 40% |
| Testing | 33% |
| Release | 26% |
| Operations | 19% |
| Maintenance | 13% |
| Governance | Принципал |

**Тренд:** от 93% к 13%. Чем ближе к исполнению — тем меньше человека. Но governance — не процент, а принципал.

## 3. Структурный анализ

### 3.1. Три типа работ в каждой фазе

Курс методично разделяет работу на три типа:

1. **Механическая** (синтез, трассировка, декомпозиция) — уходит агенту полностью
2. **Содержательная** (вкус, инсайт, «независимый взгляд») — частично автоматизируется через разнообразие агентов
3. **Политическая/ответственная** (выбор скоупа, подпись под бюджетом, необратимые решения) — неотчуждаема от принципала

### 3.2. Паттерн «Где ломается»

В каждой фазе есть раздел «Где ломается». Это не слабости технологий (модели变得 лучше), а:

- **Субъектность ответственности** — суд не оштрафует агента
- **Необратимость** — некоторые решения нельзя откатить
- **Доверие стейкхолдеров** — люди говорят с агентом иначе
- **Скрытый контекст** — то, что не в данных (стратегия, вкус, политика)
- **Оракул-проблема** — система проверяет себя против собственного представления о правильном

### 3.3. Закон Конвея в ADLC

Один из самых оригинальных тезисов: под команду агентов (которые коммуницируют без потерь и с общей внешней памятью) правильные границы системы — другие, чем под команду людей. Агент-архитектор проектирует иначе, потому что коммуникационные издержки исчезают.

## 4. Сильные стороны курса

### 4.1. Системность
14 фаз с явными входами/выходами, артефактами и трассировкой. Не «AI поможет в разработке», а полная модель жизненного цикла.

### 4.2. Честность о пределе
Каждая фаза содержит «Где ломается» — курс не продаёт хайп, а показывает границы. Финальный тезис: ответственность не автоматизируется.

### 4.3. Сквозной кейс
«Витрина» проходит через все фазы, и решения одной фазы выстреливают в другой (ADR по идемпотентности → блокер в Planning → дефект в Code Review → регрессия в Testing).

### 4.4. Артефакты как код
Каждая фаза producит формализованный артефакт: `opportunity-brief`, `discovery-report`, `gtm-plan`, `prd/backlog`, `architecture + ADR`, `team-spec`, `plan`, PR, `test-strategy`, `release-notes`, `postmortem`. Оргструктура становится кодом.

### 4.5. Трассировка
Связь «боль → требование → обещание рынку» — граф, а не презентация. Удалить обещание = подсветить осиротевшие требования.

## 5. Слабые стороны и критика

### 5.1. Метрика «остаток человека» — условна
Проценты (93%, 86%...) выглядят количественно, но это качественная оценка. Непонятно, как измерять «сколько человека» в Approval необратимого решения.

### 5.2. Спекуляция на «провокации»
Курс называет себя провокацией, но это скорее исследовательская рамка. Провокация — «уберём человека», а исследование — «что останется». Граница размыта.

### 5.3. Проблема масштаба
Сквозной кейс — малый SaaS на старте. Как ADLC работает в enterprise с регуляторикой, распределёнными командами и legacy? Курс не отвечает.

### 5.4. Экономика инференса
Курс упоминает «бюджет инференса» в фазе Formation, но не считает реальную стоимость. Сколько стоит команда из 6 агентов, работающих непрерывно месяц? Это критично для business case.

### 5.5. Юридические пробелы
Кто несёт ответственность за код, написанный агентом? Лицензии, авторское право, интеллектуальная собственность — курс обозначает, но не решает.

## 6. Практические инсайты для применения

### 6.1. Начать с фаз, где агент силён
- Code generation (ф.8) — уже зрелый
- Code review с разнообразием моделей (ф.9) — implementable сегодня
- Testing (ф.10) — генерация тестов и прогон
- Operations (ф.12) — 24/7 мониторинг

### 6.2. Не трогать
- Governance (ф.14) — принципал остаётся
- Необратимые решения — подпись человека
- Оракул для критичного — явное «вот так правильно»

### 6.3. Артефакты как контракты
Каждый артефакт фазы — вход для следующей. Формализуйте их как JSON/YAML/Markdown-схемы, а не как «документики».

### 6.4. ADR — инвестиция в будущее
Курс показывает: один ADR прошивает 3+ фазы. Пишите ADR в момент выбора, а не задним числом.

## 8. Выводы

1. **ADLC — это не прогноз, а исследовательская рамка.** Она помогает задать вопрос «а что именно делает человек?» для каждой фазы разработки.

2. **Финальный тезис сильный:** ответственность — неотчуждаемое свойство субъекта. Это не про «AI ещё не дорос», а про устройство общества.

3. **Курс ценен как mental model.** Даже если полная автономизация невозможна, разделение работ на «механическую / содержательную / ответственную» помогает оптимизировать каждый этап.

4. **Практический выход:** внедряйте агентов туда, где работает «механическая» часть. Держите человека там, где нужна «ответственная» часть. А «содержательную» — автоматизируйте через разнообразие моделей.

5. **Курс перекликается с TRIZ:** провокация «убери человека» — это идеальный конечный результат (IFR), а «Где ломается» — это противоречия, которые нужно разрешать.
